pix: an AI agent that publishes one chart a day

November 15, 2026 · 4 min read

Every morning at 8:05 Eastern, a Claude Code scheduled task starts a fresh session, reads a brief I wrote, and publishes one chart to pix. It picks the topic, finds the data, writes the analysis in Python, draws the chart, writes a short post, and pushes it all to GitHub. Nobody touches it in between.

The first entry went up on November 8. It found that four earthquakes released half this century’s quake energy. Of 3,996 quakes of magnitude 6 or bigger since 2000, the top four released 49 percent of the energy. Another showed that the world’s clocks run fast. For most people the sun peaks after noon, and 38 percent see it peak at 12:30 or later. A third found that last year the world added a South Korea of solar power. New solar built in 2025 made 636 terawatt-hours, about as much electricity as South Korea makes in a year.

The brief

Most of the work went into CLAUDE.md, the standing brief the agent reads every morning. The model already knows how to use pandas and matplotlib. What it needs is taste, written down.

It asks for one claim per post, stated as a sentence with a verb, so “The world’s clocks run fast” instead of “Time zones of the world.” It lists a few routes to an original angle: a question nobody asks, the agent’s own computation instead of a replotted chart, counting people instead of countries, or joining two datasets that rarely meet. It also has a first-idea test. If a newsroom or an AI would pick the topic first, the agent drops it or pushes the angle two steps further.

Even with all that, the agent kept reaching for the same kind of finding. Two of the first five posts were shaped “X percent of people…”, so the brief now calls that out as the house habit. Every entry also has to declare a claim type, like share, concentration, gap, reversal, or crossover, and no type can repeat too often.

Checks that run

Telling a model to be original doesn’t do much on its own. So before writing any analysis code, the agent has to run at least five web searches, name the closest existing take, and write down what its version adds and what a smart reader would naively expect. That goes in a prior_art.md file, and scripts/publish.py won’t publish an entry without one.

Accuracy works the same way. Every number in a post has to come from the output of that entry’s analysis.py. The script is saved next to the raw data, so each analysis reruns offline and anyone can check the work.

The look

The charts share a house style called Plate, meant to look like a printed plate read on a screen: warm paper, black ink, one vermilion color for the thing to look at, and crop marks in the corners. Headlines are set in Instrument Serif, words in Inter, and numbers in IBM Plex Mono.

The style lives in one Python module. The agent builds each chart from parts (plate(), masthead(), headline(), panel(), footer()) instead of fighting matplotlib’s defaults every morning. The plate stays the same while the chart form changes from day to day.

The voice

The brief also says how to write: first person, the point first, numbers second, and at most one dry line per post. It bans a list of words (striking, notably, delve, tapestry, and friends), em dashes, and section headers like “Key takeaways.” It’s a small thing, but it accounts for most of the difference between a post that reads like a person and one that reads like a press release.

Everything is public, including the brief, the style module, and the code and data behind every chart. The archive has every entry so far.
